ZenStorage — Premium Cloud Storage Dashboard Redesign

1. Project Objective

Transform the existing ZenStorage project into a premium, modern cloud storage platform with a complete dashboard experience inspired by Cloudflare, Linear, and Vercel.

This is a UI/UX transformation of an existing, functional project, not a rebuild.

The application already supports its storage features, APIs, authentication, user panel, and admin panel. Your task is to dramatically improve the visual design, layout, navigation, and user experience while preserving all existing functionality.

Work directly inside the current project and implement the changes in the actual application.

Do not simply generate a design concept, mockup, or separate demo page.

Build the redesigned UI into the existing application.

---

2. Design Direction

Create a professional cloud infrastructure dashboard with the following visual identity:

- Primary aesthetic: Cloudflare-style functionality combined with Linear-style refinement.
- Background: Deep charcoal and near-black surfaces.
- Primary accent: Electric blue.
- Secondary accents: Subtle violet and cyan.
- Typography: Modern, highly readable sans-serif.
- Layout: Structured dashboard with a persistent sidebar and contextual top navigation.
- Components: Refined cards, tables, dialogs, dropdowns, charts, and interactive controls.
- Visual density: Information-rich without feeling crowded.
- Overall feeling: A serious cloud infrastructure product, not a generic AI-generated SaaS template.

Use restrained gradients, subtle borders, carefully controlled shadows, and consistent spacing.

Avoid excessive neon effects, giant rounded cards, oversized headings, unnecessary glassmorphism, and decorative elements that reduce readability.

The design should look credible for a production cloud storage platform.

Theme Support

Implement a complete dark/light theme system.

Dark theme:

- Near-black application background.
- Slightly lighter sidebar and card surfaces.
- Subtle gray borders.
- White primary text.
- Muted gray secondary text.
- Electric blue interactive elements.

Light theme:

- Clean off-white or light-gray backgrounds.
- White cards and navigation surfaces.
- Neutral borders.
- Dark primary text.
- Consistent blue accents.

Both themes must be fully styled, not just a background color toggle.

Preserve any existing theme preferences and persistence mechanisms.

13. Technical Constraints — Extremely Important

This project already works. Preserve that functionality.

Before changing any code:

1. Inspect the existing project structure.
2. Identify the actual framework, routes, layouts, and component system.
3. Locate the existing user and admin panels.
4. Identify existing CSS, styling conventions, and design tokens.
5. Understand how authentication, authorization, and navigation are currently implemented.
6. Identify the existing data-loading and interaction patterns.
7. Determine which UI components can be reused.

Do not assume the framework is Next.js simply because files end in ".js". Inspect "package.json" and the actual project structure.

Strictly Preserve

- All backend code.
- API endpoints and request formats.
- Database schemas and queries.
- Authentication and session management.
- Authorization and role checks.
- Upload and download logic.
- File-sharing behavior.
- Bucket operations.
- API key security.
- Existing routes and URL structure.
- Existing integrations.
- Environment variables.
- Existing business logic.

This task is UI-only.

Do not redesign the backend, replace existing APIs, migrate frameworks, rewrite the database layer, or rebuild working features.

Do not remove existing functionality just because it is inconvenient to style.

Integration Rules

- Modify the actual existing pages and layouts.
- Reuse current data and event handlers.
- Preserve existing component props and interfaces unless a UI change genuinely requires an adjustment.
- Avoid duplicating pages or creating a parallel demo dashboard.
- Avoid replacing working components with mock implementations.
- Do not hardcode fake dashboard metrics.
- Do not add unnecessary dependencies.
- Do not introduce a second styling framework.
- Preserve existing mobile and desktop functionality.
- Keep changes focused and incremental.

If an existing feature cannot be understood safely, preserve its implementation and improve its presentation around it.
